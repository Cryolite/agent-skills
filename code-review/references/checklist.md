## 観点名の一覧

報告書の「観点」欄には次の名前を使う（複数なら「，」で区切る）．

| 観点名 | 主な対象 |
|---|---|
| 要件・仕様 | 意図した目的の達成，仕様との整合，実装漏れ |
| 正確性 | ロジック，境界条件，型，数値，文字列，日時 |
| エラー処理 | 例外，エラーの伝播，失敗時の後始末，再試行 |
| リソース管理 | ファイル，接続，メモリ，スレッドなどの確保と解放 |
| 並行性 | 競合状態，デッドロック，非同期処理 |
| セキュリティ | 脆弱性，認証・認可，秘密情報，暗号 |
| データ整合性 | トランザクション，マイグレーション，永続化，キャッシュ |
| 互換性 | 公開 API，設定，ファイル形式，プロトコル，バージョン |
| 性能 | 計算量，I/O，メモリ使用量，スケーラビリティ |
| テスト | テストの有無，正しさ，安定性 |
| 可読性・保守性 | 命名，構造，重複，複雑さ，コメント |
| ドキュメント | README，API ドキュメント，コメント，変更履歴 |
| ビルド・依存関係 | ビルド設定，依存の追加・更新，CI 定義 |
| 運用性 | ログ，監視，設定，展開，障害対応 |
| 移植性 | OS，実行環境，ロケール，文字コードの違い |
| 国際化・アクセシビリティ | 多言語対応，地域ごとの書式，支援技術への対応 |
| 理論的整合性 | 出典の理論（問題設定，前提条件，数式，保証される性質，計算量）との整合，数値計算による理論の前提の崩れ |
| 疑似コードとの整合性 | 出典の疑似コードとの手順，添字，更新の順序，初期化，終了条件，演算の意味の対応 |
| 公開コードとの整合性 | 著者などが公開しているコードとの細部，既定値，出力の一致，移植したコードのライセンス |

理論的整合性，疑似コードとの整合性，公開コードとの整合性は，論文や書籍などに記述されたアルゴリズムを実装するコードに適用する（[論文・書籍などのアルゴリズムの実装](#論文書籍などのアルゴリズムの実装)）．

## 要件・仕様

- 変更は意図した目的（PR の説明，issue，ユーザの説明）を完全に達成しているか．一部のケースだけを扱っていないか．
- 仕様書，API 定義，ドキュメント，既存の挙動と矛盾していないか．
- 依頼された範囲を超える変更（無関係なリファクタリング，意図しない挙動の変更）が紛れ込んでいないか．
- 仕様が曖昧な箇所で，どの解釈を採ったかが明確か．他の解釈を採る呼び出し元はないか．
- 新しい状態，列挙値，設定項目，エラー種別を，それを扱うべきすべての箇所が扱っているか（`switch`・`match` の網羅性，既定の分岐に落ちていないか）．

## 正確性

- 境界条件: 空（空文字列，空のコレクション，0 件），1 件，最大値，最小値，負の値，先頭と末尾，off-by-one（`<` と `<=`，範囲の終端を含むか）．
- null，`None`，`undefined`，未初期化の値，欠損したキー．オプショナルな値を確認せずに使っていないか．
- 数値: 整数のオーバーフローとアンダーフロー，ゼロ除算，整数除算と切り捨ての方向，浮動小数点数の誤差と等値比較，丸め方，単位の取り違え（ミリ秒と秒，バイトと文字），符号付きと符号なしの混在，型変換による切り捨て．金額を浮動小数点数で扱っていないか．
- 文字列: 文字コード，バイト数と文字数の混同，Unicode の正規化，大文字小文字の変換と比較（ロケール依存），空白や改行の扱い，エスケープ．
- 日時: タイムゾーン（naive と aware の混在），夏時間，うるう年，月末，時刻の比較，壁時計と単調時計の使い分け，日付の境界（その日の終わりを含むか）．
- 条件式: 演算子の優先順位，短絡評価への依存，否定の誤り，ド・モルガンの法則の適用誤り，条件の抜けや重複．
- 状態: 共有された可変オブジェクトの意図しない変更，参照とコピーの取り違え（浅いコピー），ループ中のコレクションの変更，状態遷移の抜け（不正な遷移を許していないか）．
- 戻り値: 戻り値やエラーを無視していないか．部分的な成功（書き込んだバイト数など）を考慮しているか．
- API の使い方: 引数の順序，単位，既定値，副作用，スレッド安全性，非推奨の API．ドキュメントで確かめずに挙動を仮定していないか．
- 再帰とループ: 終了条件，無限ループ，再帰の深さ．
- 正規表現: アンカーの有無，貪欲なマッチ，エスケープ漏れ，意図しない部分一致．

## エラー処理

- 例外やエラーを握りつぶしていないか（空の `catch`，ログだけ出して続行，広すぎる捕捉）．捕捉すべきでない例外（中断，終了要求）まで捕捉していないか．
- エラーが適切な層に伝わるか．文脈（何をしていて失敗したか）が失われていないか．元の例外の連鎖を保っているか．
- 失敗時に後始末（ロールバック，一時ファイルの削除，ロックの解放）が行われるか．中途半端な状態が残らないか．
- 再試行: 回数の上限，待ち時間の指数的な増加，冪等でない処理の再試行，再試行してよいエラーの区別．
- タイムアウト: 外部呼び出しにタイムアウトがあるか．値は妥当か．
- フォールバック（既定値で続行など）が障害を隠していないか．
- エラーメッセージ: 利用者や運用者が原因を特定できるか．秘密情報や内部構造を外部に漏らしていないか．
- ライブラリのコードがプロセスを終了させたり（`exit`，`panic`），標準出力に書いたりしていないか．CLI の終了ステータスは適切か．
- `assert` を入力検証に使っていないか（最適化で無効になる言語がある）．

## リソース管理

- ファイル，ソケット，DB 接続，ロック，一時ファイル，子プロセスを，エラー時を含むすべての経路で解放しているか（`with`，`try-with-resources`，`defer`，`using`，RAII）．
- スレッド，goroutine，タイマー，イベントリスナー，購読が，終了や解除をされずに残らないか．
- キャッシュ，キュー，バッファ，マップが上限なく増えないか．
- 大きなデータを一度にメモリに読み込んでいないか（ストリーミングで処理できないか）．
- 接続プールやスレッドプールの大きさ，枯渇時の挙動は妥当か．

## 並行性

- 共有データへのアクセスが適切に同期されているか（データ競合）．
- 確認と実行の間の競合（check-then-act，TOCTOU）．複合操作の原子性．
- ロックの取得順序（デッドロック），ロックを保持したままの I/O や長い処理，ロックの粒度．
- 非同期処理: `await` の付け忘れ，イベントループを止める同期処理，未処理の Promise・Future の失敗，キャンセルの伝播，タスクの参照の保持．
- スレッド安全でないオブジェクトの共有（日付フォーマッタ，コレクション，クライアント）．
- 分散環境: 複数のインスタンスが同時に動く場合（重複したジョブの実行，メッセージの重複配信や順序の入れ替わり）にも正しく動くか．冪等性を確保しているか．
- メモリの可視性（`volatile`，アトミック変数，メモリオーダー）．

## セキュリティ

- 入力の検証: 信頼境界（外部からの要求，ファイル，環境変数，他システムからの応答）を越えて入ってくる値を，許可リスト方式で検証しているか．型，長さ，範囲，形式．
- インジェクション: SQL，OS コマンド，LDAP，XPath，テンプレート，ログ，HTTP ヘッダ．文字列の連結ではなくパラメータ化や引数配列を使っているか．
- 出力のエスケープ: XSS（HTML，属性，JavaScript，URL の文脈ごとのエスケープ），`javascript:` スキームの URL．
- 認証: 資格情報の扱い，セッションの管理（固定化，失効），トークンの検証（署名，アルゴリズム，有効期限，発行者，対象者），多要素認証の回避．
- 認可: すべての操作で権限を確認しているか．オブジェクトの所有者を確認しているか（IDOR）．権限昇格の経路はないか．クライアント側だけの確認に頼っていないか．
- パス: パストラバーサル，シンボリックリンクの悪用，アーカイブ展開時の Zip Slip，一時ファイルの安全な作成．
- 外部への要求: SSRF（利用者が指定した URL への要求），オープンリダイレクト．
- デシリアライズ: 信頼できないデータの `pickle`，Java のシリアライズ，YAML の任意オブジェクト生成，XML の外部実体（XXE）．
- 秘密情報: ソースコード，設定，ログ，エラーメッセージ，URL への秘密情報の混入．リポジトリへの秘密情報のコミット．
- 暗号: 弱いアルゴリズム（MD5，SHA-1 による署名やパスワードの保存，ECB モード，DES），固定の IV や鍵，自作の暗号，暗号論的に安全でない乱数，秘密の値の比較に定数時間でない比較を使うこと，TLS 証明書の検証の無効化．
- パスワードの保存に専用の関数（bcrypt，scrypt，Argon2，PBKDF2）を使っているか．
- DoS: 入力の大きさや件数の上限，正規表現の破滅的なバックトラッキング（ReDoS），圧縮爆弾，無制限の再帰．
- Web: CSRF 対策，CORS の設定，Cookie の属性（`Secure`，`HttpOnly`，`SameSite`），セキュリティ関連のヘッダ．
- 権限: 最小権限の原則，ファイルのパーミッション，コンテナを root で動かすこと．
- 個人情報: 収集，ログへの出力，保存期間，マスキング．
- 依存: 既知の脆弱性を持つバージョン，タイポスクワッティング，取得元の信頼性．
- 安全な既定値: 既定で安全側に倒れているか（デバッグモード，認証の省略，全公開）．

## データ整合性

- トランザクションの境界と分離レベル．複数の更新が原子的に行われるか．外部への副作用（メール送信，メッセージの発行）とトランザクションの順序．
- 複数のデータストア（DB とキャッシュ，DB と検索インデックス，DB とメッセージキュー）の間の整合．
- マイグレーション: 元に戻せるか，大きなテーブルを長時間ロックしないか，既存のデータの移行（バックフィル），NOT NULL 列の追加と既定値，デプロイとの順序（新旧のコードが混在する期間に両方で動くか）．
- 制約: 一意性，外部キー，NOT NULL を DB 側でも保証しているか．アプリケーションの確認だけに頼っていないか．
- 削除: 連鎖削除の範囲，論理削除との整合，関連データの孤立．
- キャッシュ: 無効化の漏れ，古いデータの使用，キーの衝突．
- シリアライズ形式: スキーマの変更，バージョン管理，未知のフィールドの扱い，精度の喪失（大きな整数，小数）．

## 互換性

- 公開 API（関数，クラス，REST・gRPC のエンドポイント，イベント）のシグネチャ，挙動，既定値，送出する例外，戻り値の変更．
- CLI のオプション，終了ステータス，出力形式．設定キー，環境変数，ファイル形式，通信プロトコル，DB スキーマの変更．
- セマンティックバージョニングに従っているか．破壊的変更が告知され，移行手段や非推奨の期間が用意されているか．
- 新旧のバージョンが混在する期間（ローリングデプロイ，クライアントの更新遅れ）やロールバック時に動くか．
- 対応する言語のバージョン，ランタイム，OS，ブラウザの範囲を変えていないか．
- 依存の更新に伴う挙動の変化を確かめているか．

## 性能

- 現実的なデータ量での計算量（ループの入れ子，線形探索の繰り返し）．
- N+1 クエリ，ループ内の I/O やネットワーク呼び出し，一括処理にできる処理．
- 必要なインデックスがあるか．クエリがインデックスを使えるか．
- 不要なコピー，大きなオブジェクトの生成，文字列の連結の繰り返し．
- 頻繁に実行される経路（ホットパス）での重い処理やログ出力．
- キャッシュの効果と正しさ，ページングの有無，取得件数の上限．
- ロックの競合，同期的な待ち，タイムアウトの値．
- 起動時間，メモリ使用量，バイナリやバンドルの大きさの増加．

## テスト

- 新しい挙動，変更した挙動に対するテストがあるか．正常系だけでなく，境界値と異常系（エラー，空，最大，並行）を検証しているか．
- テストは，コードが壊れたら実際に失敗するか（何も検証していないテスト，常に成功するテスト，テスト対象そのものをモックしているテスト）．
- 期待値は仕様から導いたものか（実装の出力を写しただけではないか）．
- テストが互いに独立しているか（実行順序への依存，共有状態，後始末の漏れ）．
- 不安定さの要因（現在時刻，乱数，ネットワーク，`sleep` による待ち合わせ，並行性，ファイルシステムの順序）．
- モックやスタブが実際の挙動と乖離していないか．
- 既存のテストを削除，無効化（skip），緩和していないか．している場合は正当な理由があるか．
- テスト名と検証内容が一致しているか．失敗時のメッセージから原因が分かるか．
- 論文や書籍などのアルゴリズムの実装では，出典の数値例，理論が保証する性質（不変条件，最適性，保存則，既知の解析解），公開コードの出力と照らし合わせて検証しているか．

## 可読性・保守性

- 名前が役割を正確に表しているか．誤解を招く名前はないか．リポジトリの命名規約に従っているか．
- 関数やクラスの責務が一つにまとまっているか．長すぎる関数，深い入れ子．
- 重複したロジック（片方だけ修正される危険）．既存のユーティリティを使わずに再実装していないか．
- 使われていないコード，コメントアウトされたコード，到達不能なコード．
- マジックナンバーやマジックストリング．
- コメントが「なぜ」を説明しているか．コードと食い違ったコメントはないか．
- 抽象化の水準が揃っているか．層の境界や依存の方向を破っていないか．
- 追跡されていない TODO や FIXME．
- 既存のコードの書き方や設計と一貫しているか．

## ドキュメント

- 挙動，API，設定，CLI を変えた場合に，README，API ドキュメント，ヘルプの文言，コメント，docstring を更新しているか．
- CHANGELOG やリリースノート，破壊的変更の移行手順．
- ドキュメントのコード例が実際に動くか．
- ドキュメントの記述が実装と一致しているか（既定値，制約，エラー時の挙動）．
- 論文や書籍などのアルゴリズムの実装では，出典（書誌情報，参照した版，節・式・アルゴリズムの番号），出典の記法と変数名の対応，出典との意図した差異とその理由が，コメントやドキュメントに書かれているか．

## ビルド・依存関係

- 新しい依存は必要か．保守状況，ライセンスとの適合，大きさ，セキュリティ上の評判，既存の依存で代替できないか．
- バージョンの指定（固定，範囲），マニフェストとロックファイルの整合．
- ビルドスクリプトや CI 定義の正しさ（権限，秘密情報の扱い，外部入力の扱い，サードパーティのアクションやコンテナイメージのバージョン固定）．
- 再現可能なビルドか．生成物と生成元が一致しているか．
- コンパイルオプションや機能フラグの組み合わせで壊れないか．

## 運用性

- ログ: 障害時に原因を追えるか（識別子，文脈）．レベルは適切か．秘密情報や個人情報を出力していないか．ログが多すぎないか．
- メトリクス，トレース，アラート，ヘルスチェック．
- 設定: 既定値は安全か．不正な値を起動時に検出できるか．設定項目は文書化されているか．
- 展開: 段階的な展開，機能フラグ，ロールバックの手段，マイグレーションとの順序．
- グレースフルシャットダウン，再起動時の挙動，処理途中で停止した場合の復旧．

## 移植性

- OS の違い: パスの区切り文字，大文字と小文字の区別，改行コード，パーミッション，シンボリックリンク，予約されたファイル名．
- ロケール，文字コード，タイムゾーンへの依存（実行環境の既定値に頼っていないか）．
- シェルの違い（`bash` と POSIX `sh`），コマンドのオプションの違い（GNU と BSD）．
- CPU アーキテクチャ（エンディアン，ワードサイズ，アラインメント）．
- 言語やランタイムの対応バージョンで使えない機能を使っていないか．

## 国際化・アクセシビリティ

UI や利用者向けの文言を扱う変更の場合に確認する．

- 文言のハードコード，翻訳ファイルへの追加漏れ，複数形の扱い，文字列の連結による文の組み立て．
- 日付，数値，通貨の地域ごとの書式．右から左に書く言語への対応．
- アクセシビリティ: 代替テキスト，ラベル，キーボード操作，フォーカスの管理，コントラスト，スクリーンリーダーへの対応．

## 論文・書籍などのアルゴリズムの実装

論文，書籍，技術報告などに記述されたアルゴリズム（数式，疑似コード，文章で示された手順）を実装，移植，変更するコードには，次の 3 つの観点を適用する．出典がコメント，docstring，PR・MR の説明，コミットメッセージに示されている場合（論文名，著者名，arXiv の ID，DOI，「Algorithm 1」「式 (3)」など）のほか，教科書に載っている既知のアルゴリズムやその変種を実装している場合も該当する．出典の特定と入手は SKILL.md の手順 2 に従う．

- 出典との差異そのものは問題としない．意図した改良，正誤表に基づく修正，数値的に安定な等価変形，対象の問題に合わせた特殊化は正当でありうる．差異が結果の正しさ，理論が保証する性質，再現性に与える影響と，差異とその理由が記録されているかを確かめる．
- 出典どうしが食い違う場合（本文と疑似コード，出典と公開コード，版の違い）は，どれに従ったかが明確か，その選択が正しいかを確かめる．出典自体の誤りが疑われる場合は，正誤表，著者による訂正，後続の文献で確かめる．
- 出典の明記の不足は「ドキュメント」，出典の数値例や公開コードとの比較による検証の不足は「テスト」の観点で指摘する．

### 理論的整合性

- 問題設定: 実装が解いている問題が，出典の問題設定（入力と出力の定義，目的関数，制約，最小化か最大化か）と一致しているか．
- 前提条件: 出典の定理や保証が前提とする条件（入力が整列済み，重みが非負，行列が対称・正定値，関数が凸，データが独立同分布，グラフが連結，キーが重複しないなど）を入力が満たすことを保証しているか．満たさない入力を検出するか，文書化しているか．
- 数式の転記: 符号，添字，総和や積の範囲，転置，ノルムの種類，正規化の定数，対数の底，和と平均，不偏分散と標本分散，角度の単位．出典の記法とライブラリの規約の違い（`numpy.std` の既定は `ddof=0`，`scipy.stats` の分布は rate ではなく `scale` を取る，行優先と列優先，0 始まりと 1 始まり）．
- 不変条件と保証: 出典の正しさの証明が依存する不変条件（ループ不変条件，ヒープ条件，単調性，保存則）を，実装のすべての経路が保っているか．出典が示す性質（収束，最適性，近似比，安定性）が実装でも成り立つか．
- 計算量: 出典が示す時間計算量と空間計算量を達成しているか（優先度付きキューの代わりの線形探索，集合の代わりのリスト，疑似コードが暗黙に仮定する定数時間の操作）．
- 数値計算: 出典の理論は実数の厳密な演算を前提にしていることが多い．桁落ち，オーバーフローとアンダーフロー（`exp` の計算，確率の積），丸め誤差による前提の崩れ（正定値性の喪失，確率が [0, 1] の範囲外になる，単調性の破れ），厳密な等値比較による終了判定，許容誤差の妥当性．数値的に安定な等価変形（log-sum-exp，逆行列の代わりに連立方程式の解法）を使うべき箇所はないか．
- 境界と退化: 出典が扱わない，または暗黙に除外している場合（空の入力，要素が 1 つ，同値や同点，ゼロ除算，特異行列，退化した図形，収束しない入力）の扱いが定義されていて安全か．

### 疑似コードとの整合性

- 対応関係: 疑似コードの各行や各手順が実装のどこに対応するかを追えるか．手順の抜け，重複，順序の入れ替わりはないか．
- 添字と範囲: 1 始まりから 0 始まりへの変換，ループの範囲の上端を含むか（`for i ← 1 to n` と `range(n)`），逆順のループ，増分．
- 更新の順序: 一斉に更新すべき値を逐次に更新していないか，またはその逆（Jacobi 法と Gauss-Seidel 法の違い，前の反復の値を使うべき箇所，多重代入 `(a, b) ← (b, a + b)`）．インプレースの更新で，後で使う値を上書きしていないか．
- 初期化と終了: 初期値（∞，0，空集合，乱数による初期化），終了条件（反復回数の上限，収束判定の閾値と比較の向き，`<` と `≤`），早期の `return` や `break` の位置．
- 演算の意味: 疑似コードの演算と言語の演算の違い（負の数の整数除算と剰余，`mod` の定義，床関数と天井関数，整数の範囲，無限大や未定義値の表現）．
- 暗黙の操作とデータ構造: 疑似コードで省略されやすい操作（正規化，整列，重複の除去，コピー），仮定されたデータ構造の性質（安定な整列，キーを減少できる優先度付きキュー，順序付きの集合），同点の扱い（タイブレーク）．
- 乱数: 無作為抽出の方法（復元抽出か非復元抽出か，重み付き），分布とそのパラメータ，乱数を使う順序．

### 公開コードとの整合性

著者などが公開しているコード（公式実装，参照実装）や，広く使われている実装がある場合に確認する．比較に使うコードは，リポジトリとバージョンまたはコミットを特定する．

- 出典に書かれていない実装上の細部（ハイパーパラメータや定数の既定値，ε などの安定化の項，初期化，前処理，クリッピング，学習率のスケジュール，打ち切りの条件）が公開コードと一致しているか．異なる場合は，意図した差異として記録されているか．
- 出典と公開コードが食い違う場合に，どちらに従ったかが明記され，その選択が妥当か．
- 同じ入力と乱数の種に対して，公開コードと許容誤差の範囲で同じ出力になるか．それを確かめたテストや記録があるか．
- 言語やフレームワークが異なる場合の規約や既定値の違い（PyTorch と TensorFlow（Keras）では，Adam の ε の既定値，BatchNorm の momentum の意味，重みの初期化の既定が異なる．TensorFlow の `padding="SAME"` は非対称なパディングになりうる．行列のメモリ配置，乱数生成器）．
- 公開コードから移植・流用したコードが，そのライセンスに適合し，必要な著作権表示や出典の記載があるか．
- 公開コードの既知の不具合（issue で報告されたもの，出典の結果を再現しないもの）を引き継いでいないか．

## 混入物

変更に紛れ込みやすいものを確認する．見つけた場合は，内容に応じた観点で指摘する．

| 混入物 | 主な観点 |
|---|---|
| 秘密情報（鍵，トークン，パスワード，`.env` ファイル） | セキュリティ |
| 競合マーカー（`<<<<<<<`，`>>>>>>>`） | 正確性 |
| デバッグ用のコード（`breakpoint()`，`debugger`，一時的な出力） | 運用性 |
| コメントアウトされたコード，一時的な回避策 | 可読性・保守性 |
| 意図しないファイル（エディタの設定，OS の生成ファイル，ビルド成果物，巨大なファイル） | ビルド・依存関係 |
| 意図しない実行権限の変更，改行コードや文字コードの変更 | 移植性 |
| 変更の目的と無関係な変更 | 要件・仕様 |
